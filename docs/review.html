Codebase and database

React + Vite frontend, Node.js 22+ / Express backend, MongoDB replica set and one application Docker image. A replica set lets a change and its audit event commit together. Shared schemas and permission policy prevent UI/backend drift. No Redis: a bounded local LRU caches non-sensitive summaries; shared limits use Mongo counters.

If this PC is lost tomorrow

  1. Use the off-machine source archive or repository to recreate the application.
  2. Recover the original vault key and separate backup key from a protected secret store.
  3. Restore the encrypted snapshot into a new empty database.
  4. Verify login, counts, customer installations and credential decryption.
  5. Reconnect SMTP and provider account access, then record the restore drill.
Local Mongo and a local ZIP are not enough. An off-machine backup schedule and securely recoverable keys must be configured before relying on this for business continuity. Provider/customer POS backups are separate from the Admin database backup.

Failures we plan for

Two operators edit the same record

Every update includes a revision. Stale edits return a conflict instead of overwriting another person's changes. Record and audit writes use the same Mongo transaction.

A provider token expires or is revoked

The inventory flags recorded expiry/attention. The future deployment adapter must verify provider responses, stop on revocation and retry only safe operations. Current status is operator recorded, not a live provider probe.

The mailbox or database is unavailable

No session is issued without completed verification. Mongo outages fail closed. Keep controlled owner recovery and SMTP recovery access. Workforce OIDC/passkeys are the next hardening step before remote deployment execution.

A backup is incomplete or its key is lost

Authenticated encryption rejects corruption. Lost vault keys mean encrypted credentials cannot be recovered; providers must issue replacements. Restore drills are the evidence that a recovery kit works.

Traffic grows beyond this EC2

Bounded requests, pools, queries and rate limits protect basic resources. Customer product traffic remains elsewhere. Capacity/load testing, monitoring, backup retention and audit lifecycle must match measured use; unlimited traffic is not promised.
